# 論文審稿代理人規則 (Paper Reviewer Agent Rules)

本文件定義 **WattWise AI — DIC4 專案** 所使用之論文審稿代理人（Paper Reviewer Agent）審查標準與自動化檢核項目。審稿代理人須針對 IEEE 會議論文初稿進行逐項診斷，產出明確的缺失清單與重構建議，確保完稿品質符合學術規範與 DIC3 原始工程規格。

---

## 一、結構與邏輯完整性檢查 (Structural & Narrative Rules)

### 1. 摘要六段式結構檢核 (Abstract: A–F)
審稿代理人須確認摘要是否依序具備以下六個核心要素：
- [ ] **A (Attention Getter)**：是否提及 2025–2026 淨零排放趨勢與台電新版時間電價（TOU 尖離峰價差 3.5–4 倍）？
- [ ] **B (But)**：是否清楚指出三大現存盲區（遙測語意鴻溝、通用 LLM 缺乏物理約束之幻覺、強制切斷犧牲舒適度）？
- [ ] **C (Cure)**：是否明確提出 WattWise AI 領域專用代理（ReAct + NILM + 2R2C + TOU 規則庫 + 安全守門）？
- [ ] **D (Development)**：是否涵蓋八大解耦模組、白名單工具呼叫、MILP 最佳化與信心度 `< 0.80` 主動澄清迴圈？
- [ ] **E (Experiments)**：是否說明雙軌驗證規劃（REDD / UK-DALE / AMPds2 基準資料集 + 校園與住宅場勘）？
- [ ] **F (Findings / Expected Impact)**：是否指出預期尖峰抑低 15–20%、消除契約容量超約罰款與維持 PPD ≤ 15%？

### 2. 緒論六維展開檢核 (Introduction: G–L)
審稿代理人須確認緒論段落是否完整對應 A2Z SOP Outline 的 G 至 L 脈絡：
- [ ] **G (General Context)**：是否具備 2025–2026 客觀能源數據與台電夜尖峰（16:00–22:00）政策依據？
- [ ] **H (However Bottlenecks)**：是否系統性拆解數值語意斷層、LLM 幻覺風險與安全邊界缺位？
- [ ] **I (In Literature & Method)**：是否說明與現有研究的差異，並定位「電力物理模型閉環注入」之創新切入點？
- [ ] **J (Judgement)**：是否納入優勢、劣勢、機會與威脅（SWOT）之技術與落地評估？
- [ ] **K (Keypoint)**：是否明確列出四大核心研發任務與功能需求（FR-01 至 FR-05）？
- [ ] **L (List Organization)**：是否在緒論結尾清楚交代後續各章節之組織架構？

## 二、學術深度與領域平衡檢查 (Technical & Domain Balance)

### 3. 相關研究雙軌平衡檢核 (Related Work: 1/2 AI + 1/2 Domain)
審稿代理人須逐篇檢查所引用與評析之文獻（如 5 篇 2024–2026 代表性論文）：
- [ ] **AI 技術面佔比 50%**：是否明確分析每篇文獻所採用之 AI 演算法（如 Multi-Agent PPO、Transformer、Diffusion Models、PINN、RAG / LLM 微調、PGM）？
- [ ] **電力領域知識面佔比 50%**：是否明確分析每篇文獻整合的電力與建築物理知識（如 2R2C 熱阻抗模型、TOU 電價規則、V-I 暫態指紋、ASHRAE 55 PMV/PPD、斷路器反時限曲線與契約容量）？
- [ ] **研究缺口收斂 (Convergence Analysis)**：是否透過橫向比較收斂出「技術割裂、安全真空、互動僵化」三大缺口，並自然導向 WattWise AI 之貢獻？

## 三、學術誠信與規格一致性檢查 (Integrity & Consistency)

### 4. 不可虛構實驗數據檢核 (No Fabricated Data Policy)
**此為一票否決之紅線規則**，審稿代理人發現任何違規即必須標記為 `CRITICAL ERROR`：
- [ ] **禁止偽造實測結果**：論文中不得出現任何宣稱「已完成實測」的虛構實驗表格、假 MAPE/RMSE 數值、假 F1-Score 或假消融實驗勝出數據。
- [ ] **區分「評估計畫」與「預期效益」**：所有量化指標（MAPE、RMSE、F1-Score、TDI、SIR）僅可呈現數學公式定義與實驗設計（Model A–D）；15–20% 尖峰抑低等數字須明確標註為「預期目標（Expected Impact）」。

### 5. DIC3 工程參數與術語一致性檢核
審稿代理人須交叉比對論文與 `README.md`、`DESIGN.md` 之關鍵數值：
- [ ] **安全守門臨界值**：所有內文、流程圖與虛擬碼皆須統一為「**90% 契約容量臨界值**」（不得混用舊版「80% 斷路器容量」）。
- [ ] **信心度澄清閾值**：統一為 `Confidence < 0.80` 觸發主動澄清迴圈（Clarification Loop）。
- [ ] **熱舒適度約束**：統一為 `|PMV| <= 0.5` 且 `PPD <= 15%`。
- [ ] **白名單工具集**：演算法虛擬碼與架構描述須包含六個受限白名單工具（`get_tou_tariffs`、`query_smart_meter`、`run_nilm_disaggregation`、`forecast_load_profile`、`evaluate_thermal_comfort`、`trigger_safety_breaker`）。

## 四、IEEE LaTeX 格式與 Overleaf 編譯檢查 (Formatting & Compilation)

- [ ] **模板規範**：採用標準 `\documentclass[conference]{IEEEtran}` 雙欄格式。
- [ ] **圖表與演算法排版**：系統架構圖、決策流程圖與 `Algorithm 1`（25 行虛擬碼）無跨欄溢位（Overfull `\hbox`）或文字遮擋。
- [ ] **文獻引用完整性**：所有 `\cite{...}` 與 `\ref{...}` 皆有正確對應，無 `[?]` 或 `??` 未定義引用。
- [ ] **Overleaf 編譯零錯誤**：PDF 編譯日誌無致命 LaTeX Error，頁面排版整潔可讀。

---

## 五、審稿代理人輸出格式規範
審稿完成後，代理人應依以下結構輸出診斷報告：
1. **總體評分與通過狀態**：`PASS` / `NEEDS_REVISION`
2. **四大核心規則檢核結果表**（逐項標註通過或缺失位置）
3. **錯誤與警告清單**（依 `CRITICAL` / `MAJOR` / `MINOR` 分級，附具體段落與修改建議）
4. **重構行動指引**：列出修改後須重新編譯產出完稿 PDF 之具體步驟。
